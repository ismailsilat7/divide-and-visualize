# Divide & Visualize

A CS2009 Design and Analysis of Algorithms project demonstrating the 2D closest-pair divide-and-conquer algorithm and Karatsuba integer multiplication. It includes seeded dataset generation, a benchmark runner, and a local interactive visualizer.

## Setup and data generation

Developed and tested with Python 3.10.

python -m venv .venv
.venv\Scripts\activate        (Windows; on macOS/Linux: source .venv/bin/activate)
pip install -r requirements.txt
python generator/generate.py

(Use python3 instead of python on macOS/Linux if needed.)

generate.py recreates all 20 datasets: files of 1 MB or less go in data/, larger ones in data/large/. Each file has its own fixed seed: seed = 2026000 + the file's number used in generate.py (for example cp01 = 2026001, im01 = 2026101). All seeds are listed in data/seeds.txt.

Files above 1 MB are kept under data/large/ and are not included in the submission. They are regenerated by generator/generate.py from the seeds above.

No digit cap was applied: all million-digit multiplication files are run at full size.

Measured running times are in runner/results.csv (all 20 files, with correctness checks).

## Run the visualizer

From the repository root:

python gui/app.py

Open http://127.0.0.1:5000. Select any available input in the sidebar. Small inputs show recorded algorithm frames with Replay, Prev, Next, Reset, progress scrubbing, and speed controls. The Karatsuba threshold slider reruns the selected input. Large inputs show the exact closest-pair result or the product digit count and leading/trailing digits, together with elapsed time. Large integer products are computed exactly; the UI abbreviates their display to keep the page responsive.

The Flask server reads datasets from data/ and data/large/. Large inputs (millions of points or digits) take longer in pure Python, roughly 15 to 35 seconds for the largest files on our machine, so please wait for the result and running time to appear.

## Run all benchmarks

python runner/run_all.py

This applies both algorithms to all datasets, checks the results, and writes runner/results.csv. The full run takes a few minutes in total; the slowest files (cp04 and im04, one million points or digits) take about 30 seconds each.

## Algorithms

- algorithms/closest_pair.py sorts points once by x and y, recursively solves both halves, merges y-order, and checks the middle strip. It keeps squared distances internally and supports optional frame recording.
- algorithms/karatsuba.py recursively splits decimal operands and combines three subproducts. The ordinary multiplication base-case threshold is configurable (default: 64 digits).
- generator/generate.py creates the 20 prescribed datasets with per-file fixed seeds recorded in data/seeds.txt.
- runner/run_all.py applies both algorithms to all datasets, checks results, and writes runner/results.csv.
